# Implementation Plan

## Принципы

- двигаться поэтапно, не пытаясь реализовать весь продукт сразу;
- сначала обеспечить надёжный inbox, потом улучшать интеллект;
- сохранять каждую задачу трассируемой к требованиям;
- держать инфраструктуру минимальной до появления реальной нагрузки.

## Этап 1. Foundation + Inbox

Цель: сделать систему, в которой ничего не теряется, а входящие сообщения обрабатываются в облаке без участия локальной машины.

### Deliverables

- структура проекта;
- `.env.example`;
- первичные SQL-миграции;
- `telegram-webhook`;
- `process-inbox`;
- базовые таблицы `audit_log` и `processing_jobs`;
- базовые тесты на идемпотентность и обработку очереди.

### Критерии готовности

- текст и поддержанные вложения доходят до `Supabase`;
- пользователь получает быстрое подтверждение;
- запись появляется в очереди;
- обработка может быть перезапущена без дублей;
- DeepSeek-результат сохраняется отдельно от оригинала.

## Этап 2. Notion View Layer

Цель: показать подтверждённые сущности и useful summaries в удобном read-model.

### Deliverables

- `notion-sync`;
- mapping таблиц Supabase -> Notion;
- базовые представления для inbox, целей, проектов, weekly context;
- retry и идемпотентный upsert в Notion.

## Этап 3. Evening Dialog

Цель: ежедневный контакт в Telegram с фиксацией итогов дня и подготовкой следующего.

### Deliverables

- `evening-dialog`;
- расписание через `pg_cron`;
- хранение состояния сессии диалога;
- одно мягкое напоминание при отсутствии ответа.

## Этап 4. Weekly Review

Цель: недельный обзор по воскресеньям с summary, выводами и предложением приоритетов.

### Deliverables

- `weekly-review`;
- агрегирование событий недели;
- генерация текста обзора через DeepSeek;
- публикация в Telegram и обновление Notion.

## Отдельные инженерные требования

- correlation id во всех логах;
- status machine для `pending`, `processing`, `processed`, `failed`;
- retry с ограничением попыток и backoff;
- unit/integration tests для критичных сценариев;
- централизованный AI adapter поверх DeepSeek API.

## Что нужно от пользователя

### Для инфраструктуры

- создать проект в `Supabase`;
- создать бота через `@BotFather`;
- получить `DeepSeek API key`;
- создать `Notion integration`;
- подготовить целевые базы данных в Notion или согласовать их структуру.

### Для продукта

- подтвердить итоговый список сущностей для MVP;
- подтвердить русскоязычный tone of voice бота;
- подтвердить расписание `evening-dialog` и `weekly-review`;
- определить список типов сообщений, которые должны поддерживаться в первой версии.
